# v9.9.0-live-readonly-validation

`v9.9.0-live-readonly-validation` adds a no-mutation Prism Central scope validator for the first real AHV lab lifecycle gate.

## Highlights

- Adds `validate:ahv-live-scope-readonly` for live Prism Central inventory validation.
- Confirms the configured cluster, subnet, optional project, image, and source VM UUIDs exist before controlled clone testing.
- Blocks clone readiness when the approved source VM is powered on unless the operator explicitly reruns with `-AllowPoweredOnSourceVm`.
- Adds a lab-only `NDC_AHV_PC_POWER_FALLBACK_TO_PE=true` option so Prism Central clone tests can route VM power actions through Prism Element v2 when the PC v3 power action is unavailable.
- Keeps the validator boundary read-only: `validate:ahv-live-scope-readonly` makes no create, clone, power, delete, or infrastructure mutation calls.

## Lab Findings

- Prism Element read-only API validation passed.
- Prism Central read-only API validation passed.
- Prism Central inventory reported two clusters, one subnet, zero images, zero projects, two VMs, and categories.
- The current viable path is controlled source-VM clone, because no PC Image Service disk images were visible.
- The discovered source VM candidate must be powered off or explicitly accepted before a real clone lifecycle test.
- Prism Central accepted source VM clone and delete tasks once the source VM was powered off; the lab's PC v3 power action returned 404, so power validation now requires the explicit PE fallback switch and waits for clone completion before power/destroy.
